## 实验 1：删掉删除失败的回滚

**注入点**：`src/com/accountbook/service/AccountBookServiceImpl.java` 第 93 行

```java
} catch (StorageException e) {
    cache.add(index, removed);   // ← 注释掉这一行
    throw e;
}
```

**我的预期**：`deleteRollsBackAndKeepsOrder` 失败，缓存里只剩 2 条（少了被"删掉"的那条）。

**实际输出**：

```
1) deleteRollsBackAndKeepsOrder(com.accountbook.test.ServiceTest)
java.lang.AssertionError: expected:<3> but was:<2>
Tests run: 19,  Failures: 1
```

**结论**：命中预期。写盘失败时缓存已经删过元素了，不把这行放回去，内存和文件就不一致——用户看到"删除失败"的提示，但界面上那条记录已经没了，重启之后它又回来。这行是失败路径上唯一的兜底。

## 实验 2：把金额取整改回 Math.round

**注入点**：`src/com/accountbook/domain/Entry.java` 第 79-81 行的 `round2` 方法

```java
// 现在（修复后）
return BigDecimal.valueOf(value).setScale(2, RoundingMode.HALF_UP).doubleValue();

// 注入（修复前的写法）
return Math.round(value * 100.0) / 100.0;
```

**我的预期**：`round2KeepsTwoDecimals` 失败。

**实际输出**：

```
1) round2KeepsTwoDecimals(com.accountbook.test.EntryTest)
java.lang.AssertionError: expected:<1.01> but was:<1.0>
Tests run: 23,  Failures: 1
```

**结论**：命中预期。`1.005` 在 double 里其实是 `1.00499999999999989...`，乘 100 得 `100.4999...`，`Math.round` 取整成 100，除以 100 就是 1.0。`BigDecimal.valueOf` 走的是 `Double.toString`，拿到的是人类写下的那个 `1.005`，再按十进制四舍五入才是 1.01。金额场景下这个差别会累积。

## 实验 3：取消跨行记录的拼接

**注入点**：`src/com/accountbook/repository/FileEntryRepository.java` 第 122 行

```java
private static boolean isQuoteBalanced(CharSequence text) {
    ...
    return true;   // ← 原来是 return quotes % 2 == 0;
}
```

**我的预期**：`newlineInsideNoteSurvivesRoundTrip` 失败，读回时报文件损坏。

**实际输出**：

```
1) newlineInsideNoteSurvivesRoundTrip(com.accountbook.test.RepositoryTest)
com.accountbook.exception.StorageException: 账本文件第 1 行损坏：双引号未闭合
Tests run: 17,  Failures: 1
```

**结论**：命中预期。`save()` 写的是标准 CSV（引号包住跨行内容，本身合法），但 `load()` 按行切分，一条记录被拆成两半，第一半的引号没有配对，于是整本账本报"损坏"。这说明"写得进去"和"读得出来"必须成对验证——只测保存是发现不了的。
