## 二、逐模块生成与审查记录

### 模块 1：`domain/`（Entry、EntryType、QueryResult）

**向 AI 提的需求**：按 01 文档的领域模型，生成三个类的骨架，`Entry` 带 `validate()`。

**AI 输出**：三个类，`Entry` 的 `validate()` 里有一串 `if`，`QueryResult` 是无参构造 + 全套 setter。

**逐行审查**

| 位置 | AI 给的 | 我的判断 | 处理 |
|---|---|---|---|
| `Entry` 字段 | 六个字段，类型与 01 一致 | 采纳 | 原样保留 |
| `Entry.validate()` | 7 条 `if`，顺序 date→type→category→amount→note | 修改 | 调整顺序：把 `category` 的"空"和"超长"拆成两条，`amount` 先判 NaN/Infinity 再判 `<= 0`（否则 NaN 比较恒 false，会漏） |
| `Entry.round2()` | `Math.round(value * 100.0) / 100.0` | **拒绝** | 见 `03-问题清单.md` 第 3 条，改为 BigDecimal |
| `EntryType` | 只有 `INCOME, EXPENSE` | 补充 | 加 `displayName` 与 `toString()` |
| `QueryResult` setter | 五个字段全可 set | **拒绝** | 改为 `setEntries()` 内部拷贝 + 强制重算，汇总只读 |
| `QueryResult.getEntries()` | 直接返回 `entries` | 修改 | 返回 `Collections.unmodifiableList(entries)` |

**采纳 2 / 修改 3 / 拒绝 2。**

### 模块 2：`exception/`（三个异常类）

**向 AI 提的需求**：按作业异常表，`BusinessException extends RuntimeException`、`ValidationException extends BusinessException`、`StorageException extends RuntimeException`，各带无参和带 message 的构造器。

**AI 输出**：三个类，符合要求。

**逐行审查**

| 位置 | AI 给的 | 判断 | 处理 |
|---|---|---|---|
| 三个类的继承关系 | 完全符合作业表 | 采纳 | 原样 |
| 类体 | 空，只有构造器 | 采纳 | 原样（异常类不该有逻辑） |
| `serialVersionUID` | 未生成 | 补充 | 加上 `private static final long serialVersionUID = 1L;` |

**采纳 2 / 补充 1。**

### 模块 3：`repository/`（EntryRepository、FileEntryRepository）

**向 AI 提的需求**：接口照抄作业；实现类做 CSV 读写，一行一条，字段 `id,date,type,category,amount,note`。

**AI 输出第一版**：接口正确；实现类用 `line.split(",")` 解析，`Files.write()` 直接覆盖，`load()` 遇到任何异常都返回空列表。

**逐行审查**

| 位置 | AI 给的 | 我的判断 | 处理 |
|---|---|---|---|
| `EntryRepository` 签名 | 与作业逐字一致 | 采纳 | 原样 |
| `split(",")` 解析 | 备注含逗号就字段错位 | **拒绝** | 手写状态机 `splitCsv`，支持引号包裹、`""` 转义 |
| `load()` 任何异常返回空列表 | 会把"文件损坏"当"空账本"，下次 save 覆盖原数据 | **拒绝** | 只对"文件不存在"返回空，其余抛 `StorageException` |
| `save()` 直接 `Files.write` | 写到一半崩溃则原文件截断 | **拒绝** | 写临时文件 + `ATOMIC_MOVE` 替换 |
| 金额格式化 | `String.valueOf(double)` | 修改 | 10000000 会写成 `1.0E7`，改用 `BigDecimal.valueOf(amount).toPlainString()` |
| 坏行处理 | 没处理 | 补充 | 抛 `StorageException("账本文件第 N 行损坏：...")`，带行号 |
| 逐行解析 + 跨行 CSV | 备注含换行时写得出、读不回 | **修补** | 加 `isQuoteBalanced()`，按引号奇偶把跨行拼成逻辑记录（见 `03-问题清单.md` 第 4 条） |

**采纳 1 / 修改 1 / 拒绝 3 / 补充 2。**

### 模块 4：`service/`（AccountBookService、AccountBookServiceImpl）

**向 AI 提的需求**：接口照抄；实现类用 `ArrayList` 缓存，构造时 `load()`，增删改后 `save()`。

**AI 输出第一版**：CRUD 都有，但 `add()` 直接 `cache.add()` 后 `save()`，**没有失败回滚**；`search()` 用 `e.getCategory().contains(keyword)`，没处理 null。

**逐行审查**

| 位置 | AI 给的 | 判断 | 处理 |
|---|---|---|---|
| 构造器 `load()` | 正确 | 采纳 | 原样 |
| `add()` 失败回滚 | **没有**，save 抛异常后缓存里已经多了一条 | **拒绝** | 改缓存 → save → 失败则 `cache.remove(index)` |
| `delete()` 回滚 | **没有** | **拒绝** | 失败则 `cache.add(index, removed)`（用 index 保持顺序） |
| `update()` 回滚 | **没有** | **拒绝** | 失败则把旧对象放回原位 |
| `search()` 空指针 | `category` 或 `note` 为 null 时 NPE | 修补 | 先判 null 再 `contains` |
| `search()` 大小写 | 区分大小写 | 修改 | 关键字与字段都转小写比较 |
| `listAll()` | 直接返回 `cache` | **拒绝** | 返回 `unmodifiableList(new ArrayList<>(cache))` |
| `nextId()` | 未实现 | 补充 | `"E" + System.currentTimeMillis()` + 冲突 while 兜底 |
| 日志 | 没有调用 `LogUtil` | 补充 | add/update/delete/reload 成功与失败都记 |

**采纳 1 / 修改 2 / 拒绝 4 / 补充 2。**

### 模块 5：`controller/`（AccountBookController）

**向 AI 提的需求**：绑定六个按钮，统一捕获异常，刷新表格。

**AI 输出第一版**：`catch (BusinessException e)` 写在 `catch (ValidationException e)` **之前**。

**逐行审查**

| 位置 | AI 给的 | 判断 | 处理 |
|---|---|---|---|
| catch 顺序 | Business 在前、Validation 在后 | **拒绝** | 调换顺序（见 `03-问题清单.md` 第 1 条） |
| 空 catch | 有一处 `catch (Exception e) { }` | **拒绝** | 补上 `LogUtil.error` + `view.showError` |
| `readEntryFromForm()` | 直接 `Entry.builder()` 风格赋值，日期/金额没做格式校验 | 修补 | 加 `DateTimeParseException`、`NumberFormatException` 捕获，转 `ValidationException` |
| `onAdd` 的 id | 用表单里的 id（界面只读且为空） | 修改 | 强制 `setId("")`，让 Service 生成 |

**采纳 1 / 修改 1 / 拒绝 2 / 补充 1。**

### 模块 6：`view/`（MainFrame）

**向 AI 提的需求**：Swing 窗口，表单 + 表格 + 按钮 + 汇总栏 + 状态栏。

**AI 输出第一版**：能用，但 `getSelectedRow()` 直接拿去 `tableModel.getValueAt()`。

**逐行审查**

| 位置 | AI 给的 | 判断 | 处理 |
|---|---|---|---|
| 表格排序 | 开了 `autoCreateRowSorter(true)` | 采纳 | 保留 |
| 取选中行 | `tableModel.getValueAt(table.getSelectedRow(), 0)` | **拒绝** | 视图行号 ≠ 模型行号，改用 `convertRowIndexToModel`（见 `03-问题清单.md` 第 2 条） |
| 表格可编辑 | 默认可编辑 | 修改 | 重写 `isCellEditable` 返回 false |
| 读取表单值 | 直接 `parseInt` | 修改 | View 只返回字符串，格式转换交给 Controller |
| 是否越权 | 没有直接读写文件 | 采纳 | 符合分层 |

**采纳 2 / 修改 2 / 拒绝 1。**

**向 AI 提的需求**：用 `java.util.logging` 封装日志，输出到 `logs/app.log`。

**AI 输出**：`info(String)`、`warn(String)`、`error(String, Throwable)`。

## 三、模板残留文件 `src/App.java`

项目是从 VSCode 的 Java 模板起步的，根目录留了一个 `src/App.java`（默认包的 Hello World）。它与 `src/com/accountbook/App.java` 并存，等于项目里有两个 `main`。

- 状态：**已提交进仓库**（第一次提交时没注意）；
- 影响：不影响运行（IDE 里指定入口即可），但会造成"到底从哪启动"的困惑；
- 处理：**待删除**（删除需要在 git 里做一次 commit，见 `05-AI日志.md` 待办）。

## 四、AI 代码的总体评价

| 维度 | 评价 |
|---|---|
| 结构正确性 | 好。分层、包名、接口签名基本一次就对，不用返工 |
| 边界处理 | **差**。null、空串、文件不存在、写盘失败，第一版几乎全漏 |
| 异常处理 | **差**。catch 顺序错、有空 catch、不回滚缓存 |
| 命名与注释 | 好。方法名可读，注释不过度 |
| 隐蔽 bug | 有。`Math.round` 精度、JTable 排序行号，都属于"能跑但会错" |

**结论**：AI 适合"把骨架和样板代码写出来"，不适合"替你想清楚失败路径"。**所有 `catch`、所有回滚、所有边界判断，都得自己过一遍。**
