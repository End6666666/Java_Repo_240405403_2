## 一、改动总览

| 序号 | 改动位置 | 类型 | 一句话理由 |
|:--:|---|---|---|
| 1 | `Entry.validate()` 的职责边界 | 收窄 | id 唯一性是跨记录规则，不该由单个实体判断 |
| 2 | `QueryResult` 的可变性 | 收紧 | 汇总字段能被外部改，等于没算 |
| 3 | `Entry.round2()` | 新增 | A 版指出了 double 精度问题，却没给任何解法 |
| 4 | `EntryType` 的中文显示名 | 补充 | 中文名散落在 View 的 switch 里，改一处要改两处 |

## 二、改动 1：`validate()` 只管自己

**A 版原文**（第五节校验规则表）把「id 不存在」列为 `Entry.validate()` 的校验项，抛出 `BusinessException`。

**问题**：`validate()` 是实体方法，它只能看见自己。要判断「id 是否存在」必须访问整个集合——那是 Service 的视野。A 版这么写，会逼着 `Entry` 持有一个仓储引用，实体立刻从「值对象」退化成「知道数据库的对象」。

**改后**：

```java
public void validate() throws ValidationException {
    if (date == null)                        throw new ValidationException("日期不能为空");
    if (type == null)                        throw new ValidationException("类型不能为空");
    if (category == null || category.isBlank()) throw new ValidationException("类别不能为空");
    if (category.length() > MAX_CATEGORY_LENGTH) throw new ValidationException("类别不能超过 20 字");
    if (Double.isNaN(amount) || Double.isInfinite(amount)) throw new ValidationException("金额不是有效数字");
    if (amount <= 0)                         throw new ValidationException("金额必须大于 0");
    if (note != null && note.length() > MAX_NOTE_LENGTH) throw new ValidationException("备注不能超过 100 字");
}
```

**规则归属重新划分**：

| 规则 | 归属 | 抛什么 |
|---|---|---|
| 字段非空、长度、数值范围 | `Entry.validate()` | `ValidationException` |
| id 是否已存在、能否删除、能否修改 | `AccountBookServiceImpl` | `BusinessException` |

这样分的好处：`Entry` 完全不需要知道仓储，单元测试里 `new Entry()` 就能测全部校验规则，不用造 Service。

## 三、改动 2：`QueryResult` 只读

**A 版原文**：`QueryResult` 提供无参构造 + setter，`entries`、`totalIncome`、`totalExpense`、`balance`、`count` 都是可变字段。

**问题**：`QueryResult` 是「算好的快照」。如果外部拿到之后还能 `setTotalIncome(999999)`，那「余额」这个数字就不可信了——而这个数字恰恰是整个界面上最需要可信的一个。

**改后**：

```java
public void setEntries(List<Entry> entries) {
    this.entries = new ArrayList<>(entries);   // 拷贝，切断外部引用
    recalculate();                             // 汇总随明细走，不允许单独设
}

public List<Entry> getEntries() {
    return Collections.unmodifiableList(entries);  // 只读视图
}
```

**代价**：`setEntries` 每次都全量重算，条目多时是 O(n)。但查询本来就是扫一遍，多扫一遍不改变量级，可以接受。

## 四、改动 3：给 `Entry` 加 `round2()`

**A 版原文**（第六节可疑设计①）：指出 `amount` 用 `double` 会有精度问题，建议"汇总时用 `Math.round(x * 100) / 100.0`"。

**问题**：`Math.round(x * 100) / 100.0` 是**错的**。`1.005` 在 double 里实际是 `1.00499999999999989…`，乘 100 得 `100.4999…`，`Math.round` 取整成 `100`，结果是 `1.00` 而不是 `1.01`。A 版给的方案本身就是 bug——这是最该被抓出来的一处。

**改后**：

```java
public static double round2(double value) {
    return BigDecimal.valueOf(value)
            .setScale(2, RoundingMode.HALF_UP)
            .doubleValue();
}
```

`BigDecimal.valueOf(double)` 走的是 `Double.toString` 的十进制表示，`1.005` 会被当成字面的 1.005，再 `HALF_UP` 才得到 1.01。放在 `Entry` 上而不是工具类，是因为"金额保留两位"是业务规则，不是通用工具。

**验证**：`EntryTest.round2KeepsTwoDecimals` 断言 `round2(1.005) == 1.01`，这条用例在 A 版方案下是红的。

## 五、改动 4：`EntryType` 带上中文名

**A 版原文**（2.2 节）：只写了 `INCOME, EXPENSE` 两个常量。

**问题**：界面要显示"收入/支出"，CSV 要存 `INCOME/EXPENSE`。如果枚举里没有中文名，View 里就得写：

```java
String text = entry.getType() == EntryType.INCOME ? "收入" : "支出";
```

这段 `?:` 会出现在表格渲染、下拉框、汇总行至少三个地方，加第三种类型时要改三处。

**改后**：

```java
public enum EntryType {
    INCOME("收入"),
    EXPENSE("支出");

    private final String displayName;
    EntryType(String displayName) { this.displayName = displayName; }
    public String getDisplayName() { return displayName; }
    @Override public String toString() { return displayName; }  // 下拉框直接显示中文
}
```

`toString()` 返回中文只影响界面显示；落盘走 `name()`，仍然是 `INCOME/EXPENSE`，两边不混。

## 六、修改后的类图（只画改动的部分）

```
Entry
 ├── id : String
 ├── date : LocalDate
 ├── type : EntryType
 ├── category : String      (<= 20 字)
 ├── amount : double        (> 0)
 ├── note : String          (<= 100 字, 可为 null)
 ├── + validate() : void    throws ValidationException   ← 只管自身
 └── + round2(double) : double  static                  ← 新增

EntryType
 ├── INCOME("收入")
 ├── EXPENSE("支出")
 └── + getDisplayName() : String                        ← 新增

QueryResult
 ├── - entries : List<Entry>
 ├── - totalIncome / totalExpense / balance : double
 ├── - count : int
 ├── + setEntries(List<Entry>) : void   ← 内部拷贝 + 自动重算
 └── + getEntries() : List<Entry>       ← 只读视图
```

## 七、没有改的部分（以及为什么）

| A 版设计 | 是否保留 | 理由 |
|---|---|---|
| 余额放 `QueryResult` 现算 | 保留 | A 版论证成立：放 Entry 会算出历史余额，放 Service 会漏刷新 |
| 轻量充血（validate 在实体） | 保留 | 边界划在"单条 vs 跨条"上，很干净 |
| `amount` 仍用 `double` | 保留 | 作业签名钉死 `double`，不能改类型；精度问题用 `round2` 兜住 |
| CSV 无表头、一行一条 | 保留 | 作业明确"简单文本/CSV 即可，一行一条记录" |
