```bash
javac -encoding UTF-8 -cp "lib/junit-4.13.2.jar;lib/hamcrest-core-1.3.jar" -d bin $(find src -name "*.java")

java -Dstdout.encoding=UTF-8 -cp "bin;lib/junit-4.13.2.jar;lib/hamcrest-core-1.3.jar" \
     org.junit.runner.JUnitCore \
     com.accountbook.test.EntryTest \

## 三、运行记录

### 第 1 次：1 失败

```
Tests run: 59,  Failures: 1

1) round2KeepsTwoDecimals(com.accountbook.test.EntryTest)
   java.lang.AssertionError: expected:<1.01> but was:<1.0>
```

**定位**：`Entry.round2` 用 `Math.round(value * 100.0) / 100.0`，`1.005` 在 double 里是 `1.00499999...`，×100 得 `100.4999...`，取整成 100。

**修复**：改用 `BigDecimal.valueOf(value).setScale(2, RoundingMode.HALF_UP)`。

> 这是整个项目里**唯一由测试自动抓到的 bug**。其余问题（catch 顺序、表格取错行、CSV 换行）都是靠想和手工点出来的。

```

## 四、覆盖矩阵（功能 → 测试）

| 功能 | 覆盖情况 | 说明 |
|---|---|---|

| 修改 | ✅ ServiceTest 5–7 | 含回滚 |
| 删除 | ✅ ServiceTest 8–10 | 含回滚与顺序 |
| 关键字查询 | ✅ ServiceTest 11–12、14–15 | — |
| 类型过滤 | ✅ ServiceTest 13 | — |
| 组合查询 | ✅ ServiceTest 14 | — |
| 汇总计算 | ✅ QueryResultTest 全 7 个 + ServiceTest 16 | — |
| 校验规则 | ✅ EntryTest 1–15 | 10 条规则全覆盖 |
| CSV 读写 | ✅ RepositoryTest 全 17 个 | 含转义、坏数据、目录创建 |
| 文件损坏提示 | ✅ RepositoryTest 12–16 | 报行号 |
| **界面交互** | ❌ 无自动化 | 见下方说明 |
| **Controller 事件** | ❌ 无自动化 | 同上 |
| **日志输出** | ❌ 无自动化 | 输出副作用，不好断言 |

**为什么界面和 Controller 不做自动化**：要用 `SwingUtilities.invokeAndWait` 加事件队列刷新，测试代码量会比被测代码还多；而且在无头 CI 上跑 Swing 还不稳定。这两层的正确性用冒烟程序 + 手工点来保证（见 `04-测试报告.md`）。

**这是取舍，不是遗漏**——作业要求"覆盖正常、边界、异常"，59 个用例在 domain / repository / service 三层已经覆盖齐了。

## 五、已知的测试盲区

1. **`decimalSumDoesNotDrift`（0.1+0.2）对 `Math.round` 版本的 `round2` 仍然是绿的**。因为 0.30000000000000004 × 100 = 30.000000000000004，`Math.round` 也得 30。这个用例测不出精度 bug，真正测出来的是 `1.005` 那个。
2. **并发没测**（作业明确不做多线程）。
3. **大文件性能没测**（几万条时的搜索耗时）。
